El problema → la solución

El problema

  • Las cifras oficiales de Colombia viven en PDFs, hojas XLSX, portales y APIs distintas.
  • Cada fuente tiene su propio calendario, fecha de corte y forma de corregir datos previos.
  • Un archivo puede cambiar de formato o desaparecer sin aviso.
  • Copiar cifras a mano no deja rastro de dónde salió cada número.

La solución

  • Contrato canónico de observaciones: cada valor lleva fecha, unidad, URL de origen, hash del archivo y bandera de calidad.
  • Salud por indicador: cada serie se marca vigente, desactualizada, con advertencia o faltante según su propio umbral de frescura.
  • Compuerta editorial: la narrativa con afirmaciones más fuertes que la evidencia no se publica.
  • Paquete público cerrado: solo sale lo que está en una lista explícita, con huella SHA-256 por archivo.
  • Publicación diaria automática con GitHub Actions, sin intervención manual.

Rama ColPulse Research

Laboratorio local en research/: conectores de datos empresariales y globales, Quant Lab con validación honesta, grafo temporal e IA local supervisada. Exporta paquetes sellados con SHA-256 que el sitio verifica antes de publicar; nunca recalcula sus cifras. Ver el laboratorio.

Decisiones de ingeniería

Sitio estático en vez de servidor

El sitio completo se genera en CI y se sirve como archivos desde GitHub Pages.

Se gana: cero servidores que mantener, costo casi nulo y cada versión es inspeccionable.

Se cede: no hay consultas a la medida en tiempo real; todo se precalcula en cada build.

Paquete sellado con allowlist y SHA-256

Solo los archivos de una lista explícita llegan al sitio; el manifiesto registra tamaño y SHA-256 de cada uno y la verificación rechaza archivos inesperados.

Se gana: datos crudos, intermedios y registros internos no pueden filtrarse por accidente.

Se cede: cada página nueva exige registrarla a propósito; es fricción deliberada.

Degradación elegante en vez de fallar

Si un conector falla, el error queda registrado como estado del indicador y el resto del sitio se publica; un paquete externo inválido produce una sección vacía con un mensaje claro.

Se gana: una fuente caída no apaga el producto completo.

Se cede: el sitio puede salir con huecos, por eso la salud de cada serie es pública.

Sin datos inventados

Si un número no se puede calcular o verificar, se muestra un guion. Los paquetes de ejemplo de las pruebas van rotulados [PRUEBA].

Se gana: cada cifra visible tiene una fuente rastreable.

Se cede: a veces la página se ve incompleta; se prefiere eso a rellenar.

Humano en el circuito para la IA

En ColPulse Research la IA local solo propone tareas y borradores con citas; una persona revisa fuentes, relevancia y hechos antes de que algo avance.

Se gana: ningún sistema automático aprueba su propio trabajo.

Se cede: velocidad; la revisión humana es el cuello de botella a propósito.

Licencias respetadas

Los precios de mercado usan la clave personal de cada usuario y se quedan en el entorno local; la renta fija solo se publica si el paquete declara revisión de condiciones de uso.

Se gana: el sitio público no redistribuye datos que no puede redistribuir.

Se cede: parte del análisis vive solo en el laboratorio local.

Qué aprendí y qué sigue

Aprendizajes

  • La parte difícil no es graficar: es acordar qué significa cada fecha de corte y cada revisión.
  • Una lista cerrada de lo que se publica es más segura que una lista de lo que se excluye.
  • Las pruebas automatizadas funcionan como especificación ejecutable entre los dos módulos del proyecto.

Qué sigue

  • Construir en ColPulse Research el exportador del paquete de renta fija (curva TES), hoy pendiente; el contrato y sus pruebas ya existen.
  • Ampliar cobertura de fuentes oficiales manteniendo el mismo contrato de observaciones.

In English

ColPulse is a daily pipeline that turns scattered Colombian official statistics (PDFs, spreadsheets, APIs with different cut-off dates) into a verifiable public website, plus a local research lab. Every value follows a canonical observation contract with source URL, file hash and quality flag; each indicator carries its own freshness status; an editorial gate blocks overstated claims; and only an allowlisted, SHA-256-sealed package is published to GitHub Pages every day.

All figures on this page are computed from the repository at build time. Built by Felipe Cuello Castro, economist. Educational and portfolio project; not financial advice. Source code on GitHub.
